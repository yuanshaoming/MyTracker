## 规划依据与当前基线

当前已经具备固定步长 `SortTracker`、完整固定步长 `OCSortTracker`、CSV Replay、OpenCV 可视化和两组本地现场序列。核心仍有以下限制：

- `timestampMs` 只做非负与严格递增校验，Kalman 预测仍固定 `dt=1`；
- 生命周期仍由 `maxAgeFrames` 控制，实际间隔 127 ms 或数秒时语义不同；
- 现场序列没有稳定 person ID 真值，不能自动判断 ID 是否转移；
- 当前低置信度规则为：`[continuationDetectionThreshold, detectionThreshold)` 只续接当前 Confirmed 轨迹，不创建轨迹；弱续接后的 Lost 轨迹不得恢复；
- 现有两组现场数据适合冒烟与问题复现，但不足以覆盖实施计划列出的全部真实场景。

原实施计划建议 `lostTimeout≈1000 ms`、`removeTimeout≈1500 ms`，但当前生命周期在首次漏检时立即进入 Lost，只有 Lost → Removed 一个超时边界；用户也已确认不单独拆分“恢复期限”和“最终删除期限”。因此第三批只规划一个毫秒删除门限，不新增语义重叠的第二个超时参数。

初始毫秒门限以保持现有 8 fps 行为为目标：`maxAgeFrames=2` 在连续第三个约 125 ms 的漏检帧删除，对应约 375 ms。1000/1500 ms 仅作为 Task 14 有身份真值后可评估的候选值，不直接设为已验证默认值。

## Task 12：时间戳驱动模式与毫秒生命周期

**目标：** 在保持当前固定步长结果完全兼容的前提下，增加可显式选择的时间戳驱动模式，使不均匀帧间隔同时作用于 Kalman 预测、OC-SORT 重更新和轨迹删除。

**交付：** 公共时间模式配置、可变步长 Kalman/ORU 实现、两种 Tracker 的毫秒生命周期、Replay/可视化模式选择、数值与序列测试，以及更新后的时间语义文档。

**执行说明：**

1. 在公共配置中增加明确的 `FixedStep` / `TimestampDriven` 模式，默认必须为 `FixedStep`。新增单一毫秒删除参数，初始参考值为 375 ms；固定模式继续使用 `maxAgeFrames`，两种模式不得同时决定同一条轨迹的删除。
2. 固定模式必须逐字节保持现有 Replay 默认输出，现有 CLI 不传新参数时行为不变。不得借 Task 12 调整 IoU、OCM、置信度门限、`maxAgeFrames` 或 ID 生命周期语义。
3. 时间戳模式用 `dtFrames = elapsedMs * nominalFps / 1000` 作为 Kalman 状态转移步长，使 125 ms、8 fps 时 `dtFrames=1`。速度输出仍为像素/秒；不得在接口中混用“每帧速度”和“每秒速度”。
4. 首帧、创建轨迹的当前帧和 reset 后首帧不得凭空构造时间跨度。后续时间戳仍要求非负且严格递增；异常必须保持 update 的强保证，不改变任何 Tracker 状态。
5. 时间戳模式按“距最后一次匹配 Detection 的实际毫秒数”判断 Lost 轨迹是否过期。已经超过门限的轨迹须在本帧关联前失效，不能先接管当前 Detection 再删除；恰好位于门限的行为必须写入契约并有边界测试。
6. `age`、`hitStreak` 和 `lostFrames` 继续表示 update 调用次数，不改为毫秒值，不改变现有 `TrackResult` CSV 列。毫秒生命周期只作为内部删除依据。
7. OC-SORT 的 ORU 在时间戳模式下必须使用缺失期间真实收到的帧时间序列：各步 predict 使用对应 `dtFrames`，虚拟 observation 按经过时间而非简单帧序号插值。OCM 的 `deltaT` 本批仍保持 observation 帧窗口，不扩展为毫秒窗口。
8. 当前低置信度续接保护必须保持：弱检测不创建轨迹；弱续接后的 Lost 轨迹不能通过 OCM、OCR 或 ORU 恢复。时间化不得重新引入第 34 帧或第 85 帧的旧 ID 接管问题。
9. `tracker_replay` 与 `tracker_visualizer` 增加最小的时间模式选择，例如 `--timing fixed|timestamp`；省略时为 fixed。不要在本任务引入 INI、JSON、QSettings 或通用配置文件系统。
10. 不对大时间间隔静默裁剪。超过删除门限的旧轨迹先失效；仍参与预测的轨迹若产生非法状态，沿用现有明确失败/删除规则并通过测试记录。

**验收：**

- 125 ms、8 fps 的规则序列在两种时间模式下产生相同 ID、状态和合理数值容差内的框/速度；默认 fixed Replay 输出与 Task 10 基线逐字节一致。
- 构造 125/250/375 ms 不均匀输入，独立计算并断言预测位移；同样的帧数、不同的实际时间必须在 timestamp 模式产生不同预测，在 fixed 模式仍相同。
- 覆盖删除门限前、恰好门限、超过门限，以及长停顿后带 Detection 返回的场景；过期轨迹不得恢复旧 ID。
- ORU 覆盖不均匀缺失帧时间、按时间插值、下一帧预测和有限状态；fixed ORU 现有数值测试继续通过。
- 覆盖弱续接 → Lost → 新人进入的回归，以及双人现场序列第 31–34、79–86 帧的现有保护。
- 非法时间戳、reset、实例隔离、空检测帧和两种 Tracker 均有测试；完整 CTest 通过。
- Debug、关闭测试、可视化关闭的构建均成功；关闭可视化时仍不查找 OpenCV。
- 两组现有现场数据分别用 fixed/timestamp、SORT/OC-SORT 完整重放，记录差异但不推断身份指标。

**范围：** 不调参，不引入第二个恢复超时，不实现 ReID、完整 ByteTrack、MOTChallenge 评估、Qt 或平台适配。

## Task 13：现场测试集定版与身份标注

**目标：** 把“可观看的现场录像”转化为可冻结、可追溯、带身份真值的测试集，为自动身份回归提供可信输入。

**交付：** 数据集清单、场景覆盖表、身份标注格式与说明、获准使用的标注数据、只读完整性校验工具，以及现场数据文档。

**执行说明：**

1. 先盘点现有两组序列，按实施计划建立场景覆盖矩阵：普通单人、快速行走、停留、折返、两人并行、两人交叉、前后遮挡、栏杆遮挡、画面边缘进入/离开、多人连续进入、检测短时漏失和帧时间不均匀。缺失场景明确列为待采集，不用合成数据冒充现场数据。
2. 原始图片、Detection CSV 和时间戳保持只读。未经用户确认隐私、授权和仓库体积策略，不复制、压缩、改名或提交现场原始数据；`.DS_Store` 不进入数据集。
3. 为每条序列建立稳定 `sequence_id`、相对路径、帧数、分辨率、场景标签、采集来源/授权状态、标注状态和文件摘要。序列冻结后，内容变化必须表现为摘要变化，不得静默覆盖基线。
4. 定义最小 `ground_truth.csv`：至少包含 `frame_id,person_id,x1,y1,x2,y2,visibility,ignore`。`person_id` 只在单序列内唯一；坐标沿用核心 BBox 语义。明确部分遮挡、完全不可见、画面边缘截断、反射/海报、标注不确定和 ignore 区域的处理规则。
5. 身份真值按画面中的真实人标注，不从当前 Tracker ID 反推。允许工具辅助插值，但交叉、遮挡、进入/离开和此前出现问题的关键帧必须人工逐帧复核。
6. 现有 Detection CSV 与 ground truth 分离保存：前者是算法输入，后者只用于评估。不得把漏检补进 Detection CSV，也不得为迎合当前输出修改 person ID。
7. 增加最小只读校验工具，检查 CSV 表头、数值、框有效性、帧引用、同帧 person ID 唯一性、visibility 范围、ignore 规则、帧/图片完整性和清单摘要。工具不修改或自动修复数据。
8. 先划分固定的开发集与回归集；调参只看开发集，回归集用于最终验收，避免根据同一批关键帧反复调参后再报告结果。
9. 当前两组数据若无法确认身份真值或使用授权，只能继续作为本地观察集；Task 13 应报告阻塞，不能以“程序可读取”替代任务完成。

**验收：**

- 场景覆盖矩阵逐项给出已覆盖序列或明确缺口；至少包含一个单人完整进出和一个双人交叉/遮挡的已标注序列，才能进入 Task 14。
- 每个已标注序列的 frames、detections、images、ground truth 和清单引用一致，完整性校验零错误。
- 随机帧与全部关键帧完成可视化抽查；抽查记录包含序列、帧范围和发现/修正的问题，不声称未经复核的自动插值等同人工真值。
- 第 31–34、79–86 帧若纳入测试集，必须给出稳定 person ID 与可见性标注，并能区分离场人员和入场人员。
- 原始数据未被改写；提交内容与授权范围一致。若原始数据保持本地，文档给出可复现目录约定和缺失时的明确提示。
- 完整 CTest 继续通过；数据校验工具对合成错误样例非零退出并定位序列、文件和行号。

**范围：** 不修改跟踪算法，不调参数，不根据 Tracker 输出生成身份真值，不接入云标注服务，不擅自提交现场图片。

## Task 14：自动 Regression Test 与工程指标

**目标：** 建立“固定输入 → Tracker 输出 → 身份真值匹配 → 指标/场景断言 → 非零失败”的自动回归闭环，防止修复一个场景时破坏另一个场景。

**交付：** 无 GUI 的回归运行器、指标定义文档、T01–T10 合成场景、现场回归配置与基线、CTest 集成和可读报告。

**执行说明：**

1. 回归运行器复用现有 Replay 输入语义，可选择 SORT/OC-SORT 与 fixed/timestamp 模式；不得读取图片完成算法判断，也不得依赖 OpenCV、Qt、Python 或 GPU。
2. 逐帧以明确 IoU 门限把 TrackResult 与 ground truth 做一对一匹配。使用确定性最大匹配，ignore/低可见性处理必须先写入指标文档；禁止通过遍历顺序或 track 容器顺序决定身份。
3. 工程指标至少包括：ground-truth person 数、matched/missed、false track、ID Switch、Track Fragment、Lost 事件、平均 Track 持续时间和每人 ID Switch。逐项定义首次出现、短时不可见、重新出现、Tentative/Lost 输出和序列结束如何计数。
4. 指标名称不得暗示完整 MOTChallenge 官方兼容；如果没有实现官方协议，只称为项目工程指标，并记录与官方指标的差异。
5. 补齐实施计划 T01–T10：单人匀速、停止再移动、短时消失、两人同向、反向交叉、部分遮挡、进入、离开、偶发漏检、不均匀时间。每个场景既有输入数据，也有明确身份/状态断言；不得只断言“轨迹数量大致正确”。
6. 将第 34 帧和第 85–86 帧问题转成固定现场回归断言：离场人员 ID 不得传给入场人员；低置信度续接不得创建轨迹，也不得成为 Lost 恢复锚点。
7. 为每个现场序列建立显式期望阈值或逐场景断言。首次建立基线时记录实际值并人工审查；测试程序不得提供静默“接受当前结果/覆盖基线”的路径。
8. 报告同时包含逐序列结果和汇总结果，固定列、固定小数与 locale；至少提供适合审阅的文本/CSV 输出。相同输入连续两次结果必须一致。
9. CTest 始终运行小型合成回归；现场数据未安装时应明确跳过独立的现场回归入口，但不能把“缺数据”显示为现场测试通过。Task 14 的人工验收仍要求在 Task 13 的本地冻结数据上完整运行一次。
10. 对 fixed 与 timestamp 模式分别记录结果，不因 timestamp 模式改善某项指标就删除 fixed 基线。参数试验与正式基线分离，不在回归任务中实现自动调参搜索。
11. 增加处理耗时统计时，注明硬件、构建类型、序列、帧数、检测/轨迹规模、预热和统计口径；本任务只测 Tracker 核心处理时间，不把图片解码计入。`<5 ms/帧` 仍是目标，不是未经测量的结论。
12. 内存稳定性采用可复现的长循环重放或平台工具观察，至少证明 reset 后状态不累积；没有可靠测量工具时明确列为后续平台验收，不伪造字节级结论。

**验收：**

- T01–T10 全部由 CTest 自动运行，失败信息指出场景、帧、person ID、期望和实际值。
- 人工构造一个 ID 交换、一个轨迹碎片和一个 false track 输出，证明评估器分别准确计数，而不是只验证真实 Tracker 恰好通过。
- 当前 SORT/OC-SORT、fixed/timestamp 四种组合均可运行；默认 Replay 兼容测试与现有 49 项以上测试继续通过。
- 已标注的单人序列应达到 0 ID Switch；双人交叉/遮挡按 Task 13 基线给出实际指标和门槛，不以“肉眼正常”代替断言。
- 第 31–34、79–86 帧身份回归通过，且故意恢复旧缺陷时测试能够失败。
- 同一输入两次报告逐字节一致；非法配置、缺失数据、标注错误和基线不满足时均非零退出。
- Debug 与关闭测试构建成功；核心、Replay 和回归运行器在关闭可视化时无 OpenCV 依赖。
- 在本机冻结现场集上生成一次完整报告；没有 Windows/Jetson 实测时只报告 macOS 结果。

**范围：** 不实现完整 MOTChallenge 工具链，不自动调参，不引入 ReID，不接 Qt，不宣称 Windows 或 Jetson 性能通过。
